# Siliang Engine v0.1.5

v0.1.5 is a focused DeepSeek4 FRONT scheduling/performance release on top of
v0.1.4. It removes a correctness fence that was safe but overly broad, replacing
it with deterministic double-buffered FRONT residency and device-side stream
dependencies.

## What changed

- Replaced the single DeepSeek4 FRONT CUDA bank with two alternating banks.
- Removed the per-layer `ggml_backend_synchronize(cuda_backend)` full-device
  drain introduced by the v0.1.3 determinism fix.
- Added a CUDA all-execution-stream completion event bridge. A FRONT bank is
  reused only after all CUDA execution streams that could have consumed it have
  joined a device-side completion event; the copy stream waits on that event
  without blocking the host or draining unrelated GPU work.
- Kept bounded routed-MoE prefill opt-in and documented its capacity rule:
  `min(n_ubatch * top_k, expert_count) <= K`. For DS4, K256 permits `-ub 512`;
  K216 does not.
- Release packaging still includes `docs/CONFIGURATION.md`, so the K/ubatch rule
  and reference example ship with the Windows archives.

## Qualification

The change was built locally with CUDA 13.2 for `sm_75` on the Windows reference
workstation and exercised against DeepSeek V4 Flash expert-major.

- Bounded prefill, L2=2048 MiB, K256/R12/P12, LFU, `-ub 512`, `-tb 12`:
  - 512 processed prompt tokens: **29.91 tok/s** observed;
  - 1,101-token final prompt evaluation: **24.90 tok/s**.
- The I/O fingerprint remained in the same range as the earlier fast path:
  approximately 3.41 GiB/s while blocked, indicating the recovered time came
  from removing exposed GPU synchronization rather than faster storage.
- Fresh-start deterministic decode gate: 3/3 independent 64-token runs produced
  the same output SHA-256:
  `a8ab6cd44f5483e546ebb2969a16b15ce664cd26a300a10eff2a254b09196b19`.
- Model-free test suite: 67 passing tests, with 6 expected failures documenting
  known converter limitations.
- Strict fork provenance verification passed for the 34-path engine boundary.

These are reference-workstation observations, not universal throughput claims.
The broader cross-model performance qualification remains the v0.1.3 evidence.

## Known boundaries

- The Siliang expert arena remains Windows-only; Linux CPU and macOS Metal CI
  protect the upstream-compatible non-arena paths.
- Use `--parallel 1` whenever L1 K/R/P is enabled.
- L1 K/R/P remains intentionally incompatible with LoRA in this prototype.
- Expert-major DS4 still requires mmap in v0.1.5. The managed cache reads expert
  bytes directly from the GGUF, but the current GGML tensor loader still relies
  on mmap for the original strided expert tensor backing. Removing that backing
  safely is deferred to a later managed-tensor design; `--no-mmap` remains
  fail-closed for expert-major models in this release.
- K and L2 still maintain separate residency bookkeeping. A later prompt can
  repopulate L2 for an expert still warm in K; the current demotion path handles
  that state safely, but a single global residency directory is not yet the
  authority for both tiers.
- GPT-OSS does not use the DeepSeek4 FRONT path, so this release makes no new
  GPT-OSS performance claim.
