# Siliang Engine v0.1.8

v0.1.8 qualifies the Siliang arena for Qwen3.8 Flash Next (`qwen4exp`, 512
routed experts, hybrid recurrent/attention memory), which v0.1.7 brought from
upstream but left unqualified. The target is a local coding-agent backend on
an 8 GB GPU and 24 GB of RAM. The upstream base is unchanged (`b11188`).

## What changed

Decode:

- `--expert-cache-hybrid` runs decode bypass experts on CPU from L2 when a cost
  table (`--expert-cache-hybrid-cost`) predicts a gain; K hits stay on GPU.
- `--expert-cache-l2-pinned-mib` registers the leading part of L2 with CUDA.
  Decode and bounded-prefill copies of experts resident there go straight to
  K or R without the P memcpy.
- `--expert-cache-l1-k-decode` adds decode-only K slots in the end of the CUDA
  compute buffer, which a large prefill ubatch needs and a decode graph leaves
  idle. The extension is fitted to the measured compute buffer at startup,
  every decode graph plan is checked against it, and entering decode zeroes
  it.

Prefill:

- `--expert-cache-prefill-layer-major` (qwen4exp) runs every ubatch of a
  prompt through a layer before the next layer starts, so each layer's experts
  cross the host-to-GPU link once per prompt. On a 29k-token prompt prefill
  went from 88 to 229 tok/s.
- Disk reads and L2-to-K copies overlap per expert, and the qwen4exp indexer
  runs in bounded chunks.
- `--expert-cache-prefill-l2-retain` and `--expert-cache-staging-threads`.
- Bounded prefill supports up to 512 routed experts per layer (was 256).

Sessions and checkpoints:

- With layer-major prefill, the server passes context-checkpoint positions to
  the context, which captures the recurrent state at those positions inside
  one decode call instead of splitting the prompt. The checkpoints are
  byte-identical to the split path; a 7.4k-token first turn took 43 s instead
  of 65 s. `--no-checkpoint-ubatch` drops the per-ubatch checkpoint offsets.
- Slot save/restore writes the context checkpoints to a `.ckpt` file next to
  the slot file and reads them back, so a restored recurrent slot reprocesses
  only the new tokens.

Other:

- CUDA top-k is deterministic by default (radix select with an ordered
  compaction). `cub::DeviceTopK` gave run-to-run different results on the
  qwen4exp indexer's exact ties; it stays available behind
  `GGML_CUDA_TOPK_NONDETERMINISTIC`.
- `tools/make_expert_major_gguf.py --replace-part` swaps in externally
  quantized expert parts, which produces single-schema files.
- `--expert-cache-verify` (diagnostic) compares routed K/R slot bytes with the
  model after each decode route. Route-stats lines now cover each prefill pass
  and decode stretch.
- `docs/CONFIGURATION.md` has 32k and 64k Qwen3.8 agent profiles with the
  measured numbers, thinking-budget usage, and an opt-in q8_0 KV variant.

## Model file

[`SpeederX/Qwen3.8-Flash-Next-UD-Q2_K_XL-EM-GGUF`](https://huggingface.co/SpeederX/Qwen3.8-Flash-Next-UD-Q2_K_XL-EM-GGUF)
is the Unsloth UD-Q2_K_XL GGUF with layer 2 gate/up requantized from BF16 to
IQ2_XS (one expert schema) and repacked expert-major. The card documents the
modification and how to reproduce it.

## Qualification

The engine was built locally with CUDA 13.2 for `sm_75` and tested on the
Windows reference workstation (Ryzen 5 2600, 24 GB RAM, RTX 2070 8 GB, NVMe on a
PCIe 3.0 x4 link). The reference build is the v0.1.7 release engine.

- Model-free suite: 76 passing tests with 6 expected failures that document
  known converter limitations; `test-siliang-prefill` passes.
- Strict fork provenance verification passed for the 50-path engine boundary
  on base `b11188`.

### DeepSeek4 Flash 0731 (regression)

Decode used the v0.1.7 gate contract (temperature 0, top-k 1, seed 42, 48
warmup tokens, then 128 tokens) with the v0.1.3 DS4 profile: K216/R12/P12,
8 GiB LRU L2, FRONT rolling, prefill off. Bounded prefill used K256, `-ub 1024`
and the 7,369-token code prompt.

| Cell | Output SHA-256 | Result |
| --- | --- | --- |
| Cache disabled | `0acdf000d4af...` | same as v0.1.7 |
| L2 only | `0acdf000d4af...` | same as control |
| K/R/P + FRONT, mmap | `4390be45da14...` | same as v0.1.7 (see below) |
| K/R/P + FRONT, managed no-mmap | `4390be45da14...` | same as mmap |
| Bounded prefill, mmap and no-mmap | `b332f2378690...` | same as v0.1.7 |

Three interleaved starts per build, measured while the workstation was in
normal desktop use (absolute numbers are below the idle v0.1.7 figures):

| Path | v0.1.7 median | v0.1.8 median |
| --- | ---: | ---: |
| Decode, 128 tokens | 1.672 tok/s (1.666-1.701) | 1.666 tok/s (1.643-1.702) |
| Bounded prefill, 7,369-token prompt | 26.36 tok/s (24.48-26.56) | 37.97 tok/s (37.83-38.47) |

The prefill gain comes from copying pinned L2 experts straight to K and from
overlapping disk reads with copies.

Decode determinism: 49 of 51 v0.1.8 decode gate runs produced `4390be45da14...`.
Two runs, both during heavy daytime use of the machine, took the other branch
of the same near-tie (position 51 of the measured request, a top-2 margin of
0.026 in log-probability) and continued differently from there. The routed
K/R bytes matched the model in `--expert-cache-verify` runs, the next-token
log-probabilities of v0.1.7 and v0.1.8 are identical in normal runs, and 60
further runs under synthetic CPU, GPU and disk load plus 24 log-probability and
verify runs never flipped. v0.1.7 produced no flip in 18 runs, which is not
statistically different from 2 in 51. The cause is open.

### Qwen3.8 Flash Next (new)

Qwen3.8 ran from the single-schema expert-major file with the 32k agent
profile in `docs/CONFIGURATION.md` (hybrid decode, pinned L2, decode K,
layer-major prefill).

- Teacher-forced against the arena-disabled control on the gate prompt (64
  tokens), the arena run agreed on the top-1 token at 61 of 65 positions, with
  a mean top-10 KL divergence of 0.067 (maximum 0.82): the control computes
  every expert on CPU, the arena mostly on GPU. Two arena runs were
  bit-identical.
- Direct and staged prefill copies gave identical output (four runs, final
  engine).
- Measured during development, before the final build: `--expert-cache-verify`
  over 128 decode tokens with the decode K extension checked 49,211 routed
  slots in 442,899 sampled windows with 0 mismatches; layer-major prefill gave
  the same output as the ubatch-major path for the same ubatch split; in-batch
  context checkpoints were byte-identical to the split path; a slot restored
  with its `.ckpt` sidecar reproduced the live first-token top-10
  log-probabilities exactly.

| Measurement (32k profile) | Result |
| --- | ---: |
| Prefill, 29k-token prompt | 229 tok/s |
| Decode after that prompt | 7.9 tok/s |
| Decode on a short prompt | 8.9 tok/s |
| Decode through the Pi agent (sampling on, 5k-25k context) | 5.1-7.7 tok/s |
| 900-token increment on a cached conversation | about 16 s |

These are reference-workstation observations, not universal throughput
claims.

## Known boundaries

- The Siliang expert arena remains Windows-only.
- DS4 decode flipped at one near-tie in 2 of 51 gate runs (see Qualification);
  the cause is under investigation.
- Short prompt increments on Qwen3.8 are bounded by SSD reads: a 900-token
  increment routes to about 19,300 of the 24,576 (layer, expert) pairs, while
  a 12 GiB L2 holds 6,870 experts. On the reference machine a 20-token
  follow-up costs 2.0-2.5 s of prefill and a 900-token increment about 16 s.
- Hybrid decode makes results depend on request history: which experts run on
  CPU follows the GPU cache, and CPU and GPU arithmetic round differently.
- Decode K extension requires CUDA VMM and one expert schema across routed
  layers. Layer-major prefill needs `-b` at least as large as the prompt.
- In-batch checkpoints are not used with a draft model, speculative decoding,
  or multimodal input; those keep the split path.
- Use `--parallel 1` whenever L1 K/R/P is enabled. L1 K/R/P remains
  incompatible with LoRA.
